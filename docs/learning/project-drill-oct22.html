Part 1

What and why

Written in ASD-STE100 Simplified Technical English

What we build

  1. We build one interactive website and two documents.
  2. The website shows how one vulnerability moves through the public warning system.
  3. The main view is a map. The map shows how exploitation spreads over time.
  4. A timeline shows when each group acted: attackers, the vendor, NVD, CISA, and industry.
  5. A scanner panel shows what a defender's tool knew at each point in time.
  6. A funnel chart shows how many CVEs are found, enriched, and exploited.
  7. The policy brief has a maximum of three pages.
  8. The AI log records the models, prompts, failures, and checks.

Why we build it

  1. AI tools find more software flaws than before.
  2. More flaws mean more CVEs. NVD cannot enrich all of them.
  3. In April 2026, NIST decided to enrich only priority CVEs.
  4. NIST uses the KEV list as one priority signal.
  5. KEV lists a flaw after attackers use it. Thus, the signal comes late.
  6. PHP2Shell shows this delay. Attackers used it about 4 days before NVD gave a score.
  7. Some threats have no CVE. NVD cannot show these threats.
  8. Our policy question: how can the public system warn defenders earlier?

Part 5

Terms, acronyms, and frameworks

Plain definitions, each with an everyday comparison.

CVE Common Vulnerabilities and Exposures
A unique ID for one publicly known security flaw.

Like a case number at a police station. It names the case but says little about it.

CNA CVE Numbering Authority
An organization allowed to assign CVE IDs. Often it is the vendor of the flawed product.

Like a car maker that issues its own recall notices.

NIST National Institute of Standards and Technology
The U.S. Commerce Department agency that runs the NVD.

Like the agency that keeps the official definition of a kilogram, here for security data.

NVD National Vulnerability Database
NIST's free public database that adds detail to each CVE.

Like a library catalog. Each book gets a card with its subject, author, and shelf.

Enrichment
Adding a severity score, the affected products, and the weakness type to a CVE.

Like the nutrition label on food. Without it, you know the name but not what is inside.

CPE Common Platform Enumeration
A standard name for a product and version, so tools can match a flaw to your systems.

Like a car's VIN. Recalls match on it.

CWE Common Weakness Enumeration
A category for the kind of coding mistake behind a flaw.

Like an accident report's cause code: "ran a red light."

CVSS Common Vulnerability Scoring System
A 0 to 10 score for how bad a flaw is if someone exploits it.

Like a hurricane category. It measures strength, not whether the storm hits your town.

KEV CISA Known Exploited Vulnerabilities
CISA's list of CVEs with confirmed real-world exploitation. One of NIST's priority triggers.

Like a police list of confirmed break-in methods. Useful, but it comes after the break-ins.

EPSS Exploit Prediction Scoring System
A score for the probability that attackers will exploit a CVE within a set time window. Co-created by a RAND researcher.

Like a weather forecast's chance of rain.

EO 14028
The 2021 executive order on improving national cybersecurity. It defines "critical software," one of NIST's priority categories.

Like a building code that names which buildings need sprinklers first.

Zero-day / n-day
A zero-day is exploited before a fix exists. An n-day is a known flaw that attackers still exploit after a fix exists.

Like a lock nobody knows is broken, versus a recalled lock that owners never replaced.

RCE Remote code execution
A flaw that lets an attacker run their own commands on your machine over the network.

Like a stranger driving your car from across town.

WAF Web application firewall
A filter in front of a website that blocks known attack patterns. A stopgap before a patch.

Like a guard checking bags at the door while the broken lock waits for repair.

Honeypot
A decoy system set up to watch what attackers try.

Like a bait car the police leave out to catch thieves.

PLC / OT Programmable logic controller / operational technology
Computers that run physical processes such as pumps, valves, and power equipment.

Like the thermostat and valves of a whole factory. They are slow to patch.

Framework
Leading vs. lagging signals
A leading signal predicts a problem. A lagging signal confirms it after it happens.

Like a smoke detector versus the fire department's incident report.

Framework
Public good
Something everyone benefits from but no single buyer wants to fund alone.

Like a lighthouse. Every ship uses it; no ship pays for it.

Framework
Information asymmetry
One side knows something important that the other side does not.

Like a used-car seller who knows about the bad transmission.

Framework
Self-scoring (conflict of interest)
When a vendor CNA scores its own flaw, and NIST no longer checks that score.

Like a student grading their own exam.

Framework
RAND actor framework (RR-1700)
Sorts cyber actors into users, developers, exploiters, and securers, each with different goals.

Like a town with residents, builders, burglars, and police.

Part 6

The core argument, for a beginner

Think of the NVD as a smoke-alarm service for software. When someone finds a security flaw, it gets a case number (a CVE). NIST then adds the details that make the alarm useful: how severe the flaw is and which products have it. Security tools across the country read those details to decide what to fix first.

AI now helps people find flaws much faster, so the number of case files has exploded. NIST cannot process them all. In April 2026, it decided to fully process only some of them, mostly ones already confirmed as attacked (the KEV list) or in important government software.

The problem is timing. "Confirmed as attacked" means the fire has already started. With PHP2Shell, honeypots saw attacks about four days before NVD posted a severity score, and the KEV list still had not listed it. Some threats, like the Siemens PLC attacks, never get a case number at all, so the alarm never sounds.

The project shows this delay visually, then argues for a fix: also prioritize flaws that a forecast tool (EPSS) says are likely to be attacked, publish how fast NVD works, and spot-check the scores vendors give their own flaws. The question underneath is a classic policy one: who should pay for a warning system that everyone relies on?
